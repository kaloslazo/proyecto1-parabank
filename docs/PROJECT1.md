# Avance de Proyecto 1

## Caso

Caso 1: Banca digital · ParaBank.

## Equipo

- Kalos Lazo
- Gianpier Segovia

## Objetivo

Validar que los flujos de dinero y acceso del portal mantengan consistencia, trazabilidad y controles básicos antes de una campaña de captación masiva.

## Riesgos priorizados

| Riesgo | Impacto | Prioridad |
| --- | --- | --- |
| Transferencia con débito sin crédito o viceversa | Pérdida directa y reclamo | Alta |
| Bill pay por encima del saldo | Saldo inconsistente | Alta |
| Préstamo aprobado incorrectamente | Riesgo crediticio | Media |
| Pérdida de sesión durante una transacción | Operación ambigua | Alta |
| Historial que no refleja una operación | Pérdida de trazabilidad | Media |

## Criterio de honestidad de evidencia

El dashboard no declara defectos ni resultados de ejecución sin una prueba manual observable. Los casos parten como `Pendiente`; el equipo debe registrar el resultado, pasos reales y captura antes de cambiar el veredicto.
